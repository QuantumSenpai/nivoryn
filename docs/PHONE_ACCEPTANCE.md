# Owner's later phone acceptance

Install `app/build/outputs/apk/debug/app-debug.apk` on an Arm64 Android phone. The unsigned release requires the owner's signing key. Keep the website deployment unchanged.

1. Follow MODEL_SETUP.md: the tested export/tokenizer are already downloaded on ORBIT and their reviewed hashes are pinned in the APK. Copy both files to the phone and import them in Settings → Llama resources. Run “Test local inference”: success must explicitly say Llama generated explanation · validated references, not curated fallback. A missing-model check is not a pass. Original checkpoint files cannot be loaded as exports.
2. In airplane mode after cold start, paste a **new synthetic** supported message or URL. Run local detection, inspect actual evidence/destination, and verify actual Llama mode. Save, reopen the exact snapshot, deliberately export if needed, delete locally. Keep private messages/credentials out of recordings. A provider chosen for export controls its copy.
3. Import a rotated image, Hindi/English OCR cases, low-quality image, QR and labelled PDF page. Correct OCR before checking. Test labelled PNR/amount/date agreement and disagreement. PDFs are limited to 20 pages / 20 MB and only page 1 is extracted; issuer/booking/signature status must remain unverified. Test cancellation and the cooperative 30-second deadline.
4. Generate the safe PCAP fixtures with tools/network/make-fixtures.py, import benign/sweep captures, inspect actual structured flows and threshold findings. Repeat with an authorised real capture from the separate Linux adapter. Record unsupported protocols. Do not claim replay as live VPN monitoring or TLS plaintext visibility.
5. Import a benign signed APK under 20 MB and a corrupt file. Check identity, permissions and fingerprints without installation/execution. Real feed matches require a licensed signed indicator pack and separately pinned publisher key. Check stale/tampered/downgraded pack refusal and rollback.
6. Exercise missing/incompatible/partial model imports, reselect/resume, cancellation, overlapping operations, rollback and deletion; ensure history is retained. Use the real official model, not synthetic lifecycle-test bytes.
7. Test TalkBack, large text, light/dark, compact/large/rotated layouts, keyboard visibility, back and process recreation. The test suite is not proof of these device behaviours.
8. Run scripts/benchmark-android.py against the identified phone; additionally measure first/warm check, OCR, model load/generation, peak memory, interaction frame pacing and battery under stated conditions. Record limitations and actual values. Emulator launch data is not a phone benchmark.

Model access/resources are resolved. Actual Llama/ExecuTorch generation, real import/history and UI airplane-mode processing were verified on an Android 14 Arm64 emulator; a genuine Llama recording is on ORBIT. This does not establish physical-phone performance or battery impact. Phone acceptance remains deferred at the owner's request; Linux target hardware is also unavailable.
