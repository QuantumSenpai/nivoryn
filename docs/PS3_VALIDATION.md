## Real model and explanation policy

Runtime is dependency-locked `org.pytorch:executorch-android:1.2.0`, Arm64 CPU/XNNPACK. The tested SpinQuant export is 1,135,951,488 bytes; TikToken is 2,183,982 bytes. Exact source revisions/digests, licence and setup are in MODEL_SETUP.md. The published conversion is linked directly by the official ExecuTorch README; it is **not described as a local export or Meta-hosted `.pte`**. Official Meta source download also succeeded after owner authentication. No substitute family or external inference endpoint is used.

Every explanation word comes from actual Llama generation. JSON syntax is prefilled; the app supplies a caution disclaimer and approved remediation text. Only controlled finding facts enter the prompt. Raw messages, quotes, hosts, file contents and attacker instructions do not. The result distinguishes validated model references, local source binding for exactly one known finding, limited no-warning checks, and curated fallback. Locally attached citations are not claimed as model-generated references. All content, vocabulary, unsafe-instruction, certainty, negation, reference and action checks still apply. Unknown/multiple findings do not get implicit attribution. UNKNOWN assessments bypass inference and retain the truthful insufficient-input explanation.

The seven authored advisory fixtures are **format/guardrail smoke tests, not an accuracy dataset**. Their raw generated outputs and binding outcomes are retained in `llama-varied-smoke.json`. The earlier strict-citation policy accepted 2/7 SpinQuant outputs; a QAT+LoRA candidate executed natively but accepted only 1/7 under that same policy, so it was not activated. The current policy accepted 5/7: OTP with model references; Hinglish, URL authority and remote-control with explicit local binding; benign with no findings. Hindi and upfront-fee outputs were rejected. Later local single-finding binding is a different attribution policy and must not be presented as a model-quality comparison. Malformed JSON/unknown claims still fall back. Broad adversarial and semantic-entailment evaluation remains required; validation is not a proof against all false reassurance.

## Evaluation and performance

UCI SMS Spam Collection (Almeida & Hidalgo, 2011; DOI 10.24432/C5CC84), CC BY 4.0: raw 5574 rows, 5159 after normalised duplicate grouping, seed 228, 4128 train/1031 held out. Vocabulary fitted on training only; fixed threshold 0.99. TP 113, FP 0, TN 903, FN 15; precision 1.0, recall 0.8828125 **on that historical spam split only**. Near-template families beyond exact normalisation were not grouped. No contemporary scam/Hindi/Hinglish/worldwide accuracy is inferred. Reports/reproduction are in evaluation/README.md and the increment report directory. Raw corpus/model masters remain on ORBIT; only coefficients and attribution are bundled.

Host: Mac17,3, Apple M5, 10 CPUs, 16 GiB RAM. Android test VM: Arm64 Android 14, 4 GiB RAM, two vCPUs, software graphics, airplane mode; no physical phone or Arm Linux device connected. The native smoke measured 1,066 ms load, 1,676 ms generation and 1,024 ms to first token. The import/history pipeline measured 2,983 ms first request and 1,641 ms warm request. These are single observations, not a statistical phone benchmark. The startup/profile scripts collect process-cold launch, sampled PSS/RSS and Android frame percentiles during the real flow. Sampling and automated scrolling add overhead; OS file cache may be warm. The final 7782 ms UI profile sampled 23 times: peak RSS 1,440,240 KiB, peak PSS 1,356,613 KiB; final frame snapshot 135 frames/23 janky, p50 16 ms, p95 34 ms, p99 133 ms. One process-cold launch TotalTime was 414 ms (440 ms command wall). These are emulator observations; **60 Hz smoothness, battery and phone inference speed are not claimed**. Synthetic OCR latencies are in extraction-metrics.json, not representative-photo benchmarks.

## Security review and remaining states

Fixed regressions found in independent review: stale native stop crossing generations; output-prefix/trailing JSON acceptance; inverse exposure reassurance; cancellation during model verification; previews bypassing read/page limits; QR-only PDF loss; snapshot count/size mismatch; saved-result recreation/resave; interrupted SAF export; APK metadata control/bidi spoofing. Regression tests accompany these changes. Unsupported audio's unbounded automatic player was retired and its UI now explains how to use Text instead.

No Internet/network-state permission, broad SMS/storage access, TLS interception/CA, submitted APK execution, secret logging or cloud fallback. Maven OSV audit checked 143 locked runtime packages without indexed findings; this does not cover every native/transitive risk or establish absence of vulnerabilities. Remaining compiler/lint/upstream notices are kept visible and documented; no blanket suppression or deleted failing tests was used.

Lint cleanup removed unused foundation resources in both languages, unused icon/optional arguments, obsolete empty resource directory and KTX/modifier-order suggestions. Five warnings remain: Gradle, ExecuTorch and Robolectric upgrade suggestions (tested compatibility stays pinned); `UsableSpace` (imports deliberately require actual free space plus reserve, rather than depending on eviction of clearable caches); `MonochromeLauncherIcon` on the base adaptive icon (the API-33 variant already supplies the monochrome foreground). The final XML and successful lint runner log are retained. No rule was disabled. Earlier native-symbol stripping messages were from packaged upstream libraries, not a disabled application check.

**Implemented but not hardware-verified:** physical phone workflows/performance/accessibility, low-memory/storage behavior, Arm Linux tcpdump capture and same-UID `/proc` observations. Phone acceptance is deferred by the owner.

**Experimental:** heuristic network anomaly detection, spam proxy outside its evaluated split, broad scam/multilingual detection effectiveness and Llama advisory reliability/semantic validation.

**Blocked/unavailable:** Android live VPN monitoring, TLS plaintext inspection, general cross-app malware behavior, issuer/booking/signature authentication, audio processing, real-world signed feed provisioning, locally reproduced source export and owner-signed production release. The separate Linux adapters do not imply identical Android capabilities. Full PS3/production acceptance is not asserted while these scoped limitations remain.
